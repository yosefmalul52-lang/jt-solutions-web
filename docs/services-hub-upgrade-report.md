## 1. מה שינית

### Hero — תוצאה עסקית, לא קטלוג

| שדה | תוכן |
|-----|------|
| Eyebrow | לפי הבעיה — לא לפי רשימת שירותים |
| כותרת | כל מה שהעסק צריך כדי להפוך נראות דיגיטלית לפניות מסודרות |
| תת־כותרת | במקום לבחור שירותים טכניים, מתחילים מהמצב של העסק: אתר שלא מביא פניות, קמפיין בלי מדידה, לידים שמתבלגנים בוואטסאפ או צורך לבנות תשתית מאפס. |
| CTA ראשי | קבל אבחון דיגיטלי חינם |

### שירותים לפי בעיה (4 מסלולים)

כל מסלול מציג: **הבעיה · למי זה מתאים · מה מקבלים בפועל · התוצאה העסקית · הצעד הבא** + קישור «קרא עוד על המסלול» + CTA אחיד.

| מסלול | שפה עסקית |
|-------|-----------|
| אתר / דף / חנות | אתר או דף נחיתה שמציגים את העסק נכון ומובילים לפנייה |
| מיתוג | מראה מקצועי שבונה אמון לפני השיחה |
| אוטומציה | סדר בלידים ומעקב אחרי כל פנייה |
| שיווק | פרסום שאפשר למדוד ולשפר |

### CTA אחיד

«קבל אבחון דיגיטלי חינם» ב-Hero, בכל מסלול שירות ובבלוק סיום. חריגים ניווטיים בלבד: «ראה עבודות לדוגמה», «קרא עוד על המסלול», תוויות כרטיסי הדחיפות («למסלול…»).

### UX/UI

- היררכיה ברורה: Hero → אבחון → מסלולים → גישה מהירה → CTA סיום
- כרטיסים קצרים עם `min-h` לכפתורים/קישורים במובייל
- `overflow-x-hidden` על העמוד
- ללא אנימציות כבדות חדשות
- Metadata עודכן לשפה עסקית — ללא canonical עם hash

**לא שונה:** עמוד הבית, עמודי שירות פנימיים, מנגנון הטופס, redesign גלובלי.

## 7. השלב הבא המומלץ

1. **שדרוג עמודי שירות פנימיים** — `/services/websites`, `/services/automations`, `/services/digital-marketing`, `/services/branding` — באותה שפת בעיה/תוצאה.
2. **סנכרון anchors** — לוודא ש-`#corporate`, `#landing`, `#ecommerce`, `#whatsapp`, `#site-integration` קיימים ומותאמים בעמודי המשנה.
3. **עדכון JSON-LD** ב-`lib/seo/organization.ts` — לשקף את 4 המסלולים החדשים.
4. **בדיקת Lighthouse במובייל** ל-`/services` — overflow, tap targets, CLS.
5. **Prefill טופס** — לוודא ש-`contactHref` מכל מסלול מגיע לטופס עם `service` מתאים (כבר מחובר דרך `buildContactHref`).
